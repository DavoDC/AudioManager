Global date-range selector (top right) re-renders the whole dashboard against the chosen window - selecting a value here updates the Year and Batch charts in this mockup as a working demo of the pattern; the real build should apply it dashboard-wide.

Why no daily "additions calendar" heatmap: David integrates new music in one big batch every 2-4 weeks (see AudioManager/CLAUDE.md), not a little each day - a daily heatmap would be empty almost every day and spike hard on integration day, which reads as broken rather than insightful. Replaced with a per-batch bar chart and batch-grouped "Recent Additions," both of which read correctly against real batch-shaped data.

TIER G5 - far future, not required this round

Last.fm read-onlySTRETCH GOAL

No OAuth needed - user.getRecentTracks and related read endpoints work with just a free API key, no auth flow. Lowest-effort real integration available: recently-scrobbled tracks overlaid on Library Browser, or a small "never scrobbled" cross-reference panel. Attempt only if Statistics/Integration/Library/TagFix are done with budget to spare.

Spotify read-onlySTRETCH GOAL

Needs Authorization Code + PKCE flow: register an app in the Spotify Developer dashboard, redirect to localhost, exchange a code for a token. More setup than Last.fm (David needs to create the app registration himself first) but still no client-secret storage risk. Only attempt after Last.fm, and only if there's clear budget remaining.

Both are explicitly optional this round - TIER G5 in GUI-ROADMAP.md remains "far future" as the floor. This tab is an invitation to go further if core tabs finish early, not a requirement.
